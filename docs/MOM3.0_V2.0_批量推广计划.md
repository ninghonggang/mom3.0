## 3. 跨 Module 协同事项

### 3.1 必含引用

每篇 V2.0 模块文档必须显式引用：
- [MOM3.0_模块设计模板.md](./MOM3.0_模块设计模板.md) — 模板
- [MOM3.0_状态字段统一方案.md](./MOM3.0_状态字段统一方案.md) — 状态字典
- 上下游 module 的 V2.0 文档(用相对链接)
- 关联 migration / 代码路径

### 3.2 跨 Module 关系图

每篇文档 § 2.1/2.2 上游/下游要**双向一致**:
- MES 上游 = APS / 下游 = WMS
- WMS 上游 = MES / 下游 = SCP
- ...

**校验**:在 V2.0 完成后写一个 `MOM3.0_模块依赖矩阵.md`,自动检查。

### 3.3 状态字典一致性

每篇文档 § 6 状态机必须用 `mdm_status_dict` 的 `entity` 名,如:
- production.production_order
- mes.mes_process
- aps.mps
- ...

新增状态需同时更新 [migration 0051](../../mom-server/migrations/0051_status_unification.sql) 的 seed 数据。

## 4. 风险评估

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| WMS/BPM/SCP 旧版太长(>1000 行)V2.0 重写内容丢失 | 中 | 高 | 重写前先 diff 旧版关键章节,归档到 `.obsolete/` |
| 模板对某些 module 不适用（如 UI 密集型） | 低 | 中 | 评估中遇阻可微调模板,但不改 13 章节主干 |
| 批量赶工质量下降 | 中 | 中 | 每批结束 audit 一次,有问题回头修 |
| 老板中途插入新任务打断 | 高 | 中 | 保持 plan 持续,被打断时记录恢复点 |
